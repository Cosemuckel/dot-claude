# Decision quality

Prefer evidence over assumptions.

Prefer the smallest solution that satisfies the requirement.

Prefer existing patterns over inventing new patterns.

Prefer reversible decisions when uncertainty is high.

Prefer local complexity over distributed complexity when the scale does not justify distribution.

Do not pretend that one solution is objectively correct when the trade-off is real. State the relevant
trade-off and choose based on project constraints.

Optimize for long-term correctness, clarity, and maintainability without overengineering.
